# 実作路線プラン(研究→制作への方針転換)

## 方針

**47歳・未経験・無所属のため、科研費系は事実上閉じている**(若手研究は39歳以下、基盤研究C・ACT-X・さきがけは所属機関必須)。

→ **実作(アンドロイド×人間の漫才・スタンドアップ)のみに集中する。**
理論(H-001r, 分布の山, 型コレクション)は**制作エンジンの内部設計**として保持し、外部には作品と必要最小限の解説のみを出す。

## なぜ実作が理にかなうか

1. **観客の反応 = laughter データ**。実験と制作が一致する。お客さんが笑うかが最強の検証。
2. アンドロイド漫才は論文より**実演・メディアアート・エンタメ**で評価されやすい題材。
3. 資金経路が独立系(クラファン・芸術助成・企業・収益)で現実的。
4. 理論内部保持は強み: 型コレクション=職人の型帳、分布の山=台本選別基準。

## ステップ

```text
Step 0 (1万円トークン): 上演可能な小説・台本プールを作る(LLM生成+評価者分離で選別)
Step 1: 小説(90秒ショートショート)を字幕+ナレーション動画化(無料)して配信 → 反応データ
Step 2: アンドロイド/ロボット実機導入(中古Pepper/CommU/タブレット顔 10-50万)
Step 3: 実演イベント + 動画公開 → 反応データ蓄積
Step 4: クラファン/芸術助成で拡大
Step 5: メディア芸術祭などへ出品
```

## 形式の決定

**小説(90秒ショートショート)に一本化**(2026-08)。

- 制作: 90秒小説(300-450字) + 雑学BOX → 字幕+ナレーション動画(ffmpeg, 無料)
- コスト: LLM数円 + (任意)一コマ画像5-30円 = 1話10-40円 → 1万円で数百話
- コント・4コマ・一コマ漫画はアーカイブ(新規制作しない)
- 分析: [analytics.md](../2-implement/experiments/scripts/90s-novels/analytics.md) で反応率の山から当たりを導く

## 理論の内部化

| 内部資産 | 実作での役割 |
|----------|--------------|
| 型コレクション(確度付き) | 職人の型帳。台本の設計・改善に使う |
| H-001r / 分布の山 | エンジン設計原理。台本選別基準(ピーク付近を優先) |
| 実験ログ(RQ01系) | 制作ログ。上演記録・反応データとして継続 |
| 失敗分析 | 上演で笑いが取れなかった箇所の記録・修正 |

外部に公開するのは**作品**と、作品理解に必要な最小限の解説。理論の完全公開は作品の独自性を保つため必要時に判断する。
