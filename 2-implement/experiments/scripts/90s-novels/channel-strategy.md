# チャンネル戦略(分割すべきか)

## 結論

> **まず1チャンネルで全組合せを撃つ。分割はanalyticsデータが出てから。**

前提が「どれが当たるかわからない」なので、チャンネル分割は「予測」であり、前提と矛盾する。分割はデータ(反応率の山)で判断する。

## 理由

1. **分割は予測である** — 前提が「当たり不明」なら、まず全組合せを1チャンネルで撃って山を見つける
2. **データ不足期の分割はアルゴリズム学習を分散させる** — YouTubeはチャンネル単位で視聴者層を学習する。20-30本もない段階で2つに分けると、どちらも育たない
3. **metrics が単純** — 1チャンネルなら分析の山が1つ。チャンネル別集計の手間と誤差が省ける
4. **チャンネルの資産価値** — 1チャンネルで当たりが出れば、そのチャンネル自体に視聴者資産が蓄積する

## 1チャンネル運用のコツ

- **シリーズ(プレイリスト)で整理**: 「90秒ほっこりSF」「株式投資SF」「風刺4コマ」等。動画ごとではなく系列で管理
- **サムネ・タイトルでジャンル明示**: 視聴者に「このチャンネルはこういうの」を伝える(タグ・シリーズ名)
- **投資系は最初から「シリーズ」として分離管理**: 金融的注意書き・収益化審査リスクがあるため、完全なチャンネル分割はデータ後でも、運用上は別系列として扱う

## 運用モデル(確定): チャンネル内チャンネル

**1チャンネル = 放送局。番組(プレイリスト) = チャンネル内のチャンネル。**

```text
YouTubeチャンネル(1つ)
 ├── 番組「夜の月」(プレイリスト) = 内部チャンネル
 ├── 番組「夜の水」(プレイリスト) = 内部チャンネル
 ├── 番組「アンドロイド独演」(プレイリスト) = 内部チャンネル
 └── 番組「風刺4コマ劇場」(プレイリスト) = 内部チャンネル
```

- 各番組は OP/ED・番組名・サムネ色を固定 → 視聴者には「別チャンネル」のように見える
- プレイリスト購読で「番組単位」の視聴者を育てられる
- 番組ごとに metrics を集計(内部チャンネルごとの業績評価)
- **内部チャンネルで足りる限り、分割しない。** 分割は、プレイリスト・番組ブランドでは吸収できない差が出てから

## 分割の判断基準(データが出てから)

以下のいずれかが確認できたら分割を検討する:

| 基準 | シグナル |
|------|----------|
| 山の分離 | 反応率の山が2つ以上に明確に分離(例: ほっこり系とこき下ろし系が別の山) |
| 視聴者属性の乖離 | 系列ごとに視聴時間帯・年齢層・男女比が異なる |
| 混在のペナルティ | ある系列が他系列の視聴率を下げている(アルゴリズムが混在を嫌うサイン) |
| 規制・収益化 | 投資系・風刺系が収益化審査やコンプライアンス上、別管理が必要になった |

## タイミング目安

```text
バッチ1(30本程度)を1チャンネルで配信 → 1-2ヶ月データ蓄積
  ↓ 反応率の分布を確認
山が1つ → そのまま1チャンネルで重点増産
山が2つ以上に分離 → その時点で分割(データ駆動)
```

## データ上の注意

- 分割判断は**最低30本・1-2ヶ月**のデータで行う(1-2本の結果で分割しない = プロジェクト原理: 1結果で改訂しない)
- コメント・保存(シェア)は再生数より「刺さり」のシグナルが強いので、分割判断では反応率と完視聴率を主指標にする
