# アナリティクス駆動の量産(どれが当たるかわからない前提)

## 前提

> **どれが当たるかは、誰にもわからない。**
> だから、多様な組合せを量産して配信し、**analytics から当たりを導く**。

予測で絞らない。データで山(ピーク)を見つける。これは「分布の山」(H-002o)の実運用そのもの。

## 指標(作品ごと)

| 指標 | 定義 | 意味 |
|------|------|------|
| 再生数 | 動画再生回数 | 露出(タイトル・サムネの効き) |
| 完視聴率 | 最後まで見た割合 | **90秒動画の生死線**。本文の質 |
| 高評価率 | 高評価/再生 | 共感・笑いの proxy |
| コメント数 | コメント件数 | 反応の深さ |
| シェア/保存 | 拡散・保存 | 「誰かに見せたい」= 最も強い反応 |

## 導出シグナル

```text
反応率 = (高評価 + コメント + シェア + 保存) / 再生
コメント感情分類: 笑い / なるほど(雑学) / ほっこり / 風刺(刺さった) / 反論
```

- 反応率が基準(例: 5%)を超えた作品 = 「当たり」候補
- コメントの感情分布で「何が刺さったか」(笑い? 雑学? ほっこり? 風刺?)を特定

## 帰属(どの組合せが効いたか)

全作品に **ID + 軸タグ(軸A × 軸B × 軸C)** を付与する([registry.md](registry.md))。

集計:

```text
軸A(世界観)ごとの平均反応率
軸B(トーン)ごとの平均反応率
軸C(雑学ジャンル)ごとの平均反応率
組合せごとの反応率分布 → ピークの特定
```

## 分析ループ(分布の山として評価)

```text
バッチN(多様に撃つ: 20-30本)
  ↓ 配信(動画化は無料)
  ↓ analytics 集計(1-2週間)
  ↓ 反応率分布の山(ピーク)を特定
  ↓ ピーク周辺の組合せを重点増産
  ↓ 外れた組合せは失敗として記録(failure taxonomy)
  ↓
バッチN+1
```

## しきい値の運用

- 反応率 上位20% = 「当たり」→ ピーク周辺を重点的に
- 反応率 下位20% = 「失敗」→ 捨てず記録(なぜ外れたか: 題材が固い/トーンが薄い/雑学が難しい)
- データが溜まるまで(最低30本)は、軸を絞らない

## 理論との接続

- 「当たり」の反応率分布 = 笑い・共感の**分布の山**(H-002o)
- 反応がゼロの作品 = trivial_deviation(刺さらない) / uninterpretable(難しすぎ) の実データ
- コメントの感情 = 人間の laughter の proxy(Phase 1 相当)
