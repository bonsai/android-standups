# 型: 不一致-解決 (Incongruity-Resolution)

## 確度

**A** — 笑い研究で最も確立された理論の一つ(incongruity-resolution)。文献で確立。自プロジェクトの RQ01b 構造評価は間接的支持を与える。

## 型の説明

観客がある秩序・期待を構築した後、それと矛盾する要素が現れ、**その矛盾を解決できる解釈**が提示されると笑いが生じる。単なる不条理(解決不能)とは異なる。

```text
秩序・期待
  ↓
矛盾(不一致)の提示
  ↓
解決可能な解釈
  ↓
笑いの可能性
```

## 典型的な構造

1. 秩序を確立する(誰もが知っている前提)
2. 期待を確立する(次にこうなるはず)
3. 矛盾を提示する(期待を裏切る)
4. 矛盾を解決する解釈を残す(「ああ、そういうことか」)

## 実例

- RQ01b integrated-js: 型は「動けば型」→ 矛盾(型がないのに型という)が「動くことこそが型」という解決可能な解釈になる
- RQ01b integrated-py: 「インデントが正しいので動いてます」→ 矛盾(インデントは仕様ではない)が「うちの環境の仕様」で解決される

## 対応 MicroSkill

- misdirection(期待を別方向へ)
- incongruity(矛盾の提示)
- literal-interpretation(字義と慣用のズレ)

## 証拠

- 文献: incongruity-resolution 理論(笑い研究の主要パラダイム)
- RQ01b: deviation が integrated +2.0、surprise +2.3 → 矛盾の提示と意外性の寄与を間接支持
- RQ01b: baseline は deviation 3.3 と低く、矛盾の提示が弱い出力ほど面白さスコアが低い(humor 3.3)

## 反例・限界

- 矛盾が大きすぎると解決不能になり、笑いにならない(uninterpretable_deviation)。RQ01b では understandability が integrated で −0.7(5.0)と下がっており、矛盾の大きさと解釈可能性のトレードオフを示唆
- 解決を説明すると死ぬ(explained_joke)。矛盾の解決は観客側に委ねる

## 次に測ること

- 矛盾の大きさ(deviation 強度)と humor の関係を連続的に測定し、「最適ズレ領域」を確認する
