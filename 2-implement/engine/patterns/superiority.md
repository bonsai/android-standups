# 型: 優越 (Superiority)

## 確度

**A** — 笑い研究の古典理論(superiority theory)。文献で確立。RQ01 / RQ01b の「こき下ろし」系シードはこの型の上に成り立つ。

## 型の説明

誰か(あるいは何か)が愚かさ・失敗・欠陥を晒すのを見て、観客が「自分はその対象より上だ」と感じると笑いが生じる。こき下ろし・貶し・失敗の暴露が典型。

## 典型的な構造

1. 標的の欠陥・失敗を提示する
2. 観客が標的を上回る視点を取れるようにする(観客はその欠陥に陥っていない)
3. 欠陥をさらに強調する(エスカレーション)

## 実例

- RQ01: Java の「設計書 30 ページ」「Java を使うための Java」— 言語の欠陥(複雑さ・冗長さ)を晒す
- RQ01b integrated-php: 「3000 回 echo」「入力を受け付けない」— 古い作法への優越
- RQ01b integrated-js: 「型は動けば型」— 型なし言語への優越

## 対応 MicroSkill

- exaggeration(欠陥の誇張)
- deadpan(欠陥を平然と述べる)
- understatement(欠陥を軽く扱うことで逆に強調)

## 証拠

- 文献: superiority theory(Plato / Hobbes 系譜)
- RQ01 / RQ01b: 全 7 本の生成物が「こき下ろし」型で、欠陥の提示は全本で機能
- RQ01b integrated-php が最高 humor スコア(6/7)を記録 — 欠陥の提示 + エスカレーションの組合せが最も効いた

## 反例・限界

- 優越だけで作ると「ランダムな悪口」になる(RQ01 prompt の制約に明記)。標的の欠陥は観客に共有された秩序(世界知識)と接続する必要がある
- 観客自身が標的の立場だと笑えない。標的選定は文化的依存(cultural_dependency)リスク

## 次に測ること

- 標的の共通知識度(エンジニア知識 vs 一般知識)と笑いの関係
- 優越単独 vs 優越+不一致-解決の比較
