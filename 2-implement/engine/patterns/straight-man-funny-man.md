# 型: ボケとツッコミ (Straight Man / Funny Man)

## 確度

**C** — 自プロジェクト全 7 本の生成物で話者構成として採用(単一観測の蓄積)。漫才の基本構造との対応は文献的にも確立しているが、役割の効果そのものは未定量。

## 型の説明

二人の話者に固定の役割を与える。片方(ボケ)は逸脱を生み、もう片方(ツッコミ)は逸脱を指摘・正そうとする。役割の固定が観客に「次の逸脱」の期待を作る。

```text
ボケ: 逸脱を産出
ツッコミ: 逸脱を検出・指摘
→ 観客: 役割を知っているので期待が構築される
```

## 典型的な構造

1. 役割を確立する(新人=ボケ寄り、先輩=ツッコミ寄り)
2. ボケが逸脱を産出する
3. ツッコミが指摘する(だが止まらない)
4. 逸脱の連鎖の中で役割が徐々に崩れる(先輩までボケに引き込まれる)

## 実例

- RQ01: 新人(ボケ)が「3行で書けました」と逸脱を産出、先輩(ツッコミ)が「それJavaで?」と受ける。最後は先輩自身が「会社員の話だ」とボケる
- RQ01b integrated-js: 先輩が最後までツッコミを続けるが、「本番に聞いてください」に引きずり込まれる
- RQ01b integrated-py: 先輩が「バグの直し方だろ、それは」とツッコミ、新人が「直った気がします」で受け流す

## 対応 MicroSkill

- setup(ツッコミのための誘導)
- tag(ボケの後始末)
- character-switch(役割の崩れ)

## 証拠

- RQ01 / RQ01b: 全 7 本が新人/先輩の役割固定で生成され、構造スコアは integrated で機能
- 役割の効果そのものを条件比較した実験は未実施(単一観測)

## 反例・限界

- 役割が完全に固定されたままだと平坦になる。役割の「崩れ」(先輩がボケる)が反転の準備として機能
- 役割を確立するための序盤の行が冗長だと no_clear_pattern

## 次に測ること

- 「役割固定あり」vs「役割なし(一人喋り)」の対照比較
- 役割の崩れ(character-switch)の位置と punchline スコアの関係
