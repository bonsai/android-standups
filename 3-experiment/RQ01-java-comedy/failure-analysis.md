# RQ01 Java Comedy — Failure Analysis

## Purpose

Preserve weak, failed, ambiguous, or non-funny outputs as research data. Failed outputs must not be discarded merely because they are poor.

## Evaluation rule

A failed comedy output is evidence about the limits of the current prompt, guide, model, premise, or evaluation method.

## Record

For every failed output, record:

- seed
- model
- prompt version
- guide version
- output
- human reaction
- AI evaluation
- structural scores
- suspected failure mode
- proposed revision

## Failure taxonomy

```text
no_clear_pattern
weak_expectation
trivial_deviation
uninterpretable_deviation
over_escalation
weak_reversal
explained_joke
weak_punchline
poor_timing
character_inconsistency
cultural_dependency
technical_inaccuracy
AI_human_disagreement
```

## Current specimen

The first Java comedy story is retained as a specimen regardless of whether it is judged funny. No human laughter result has yet been recorded.

## Research principle

Do not optimize only for successful outputs. Failed outputs are required to identify the boundary between effective and ineffective comedy generation.
